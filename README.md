# dsh-attachment · 依恋

给 DSH 装一套**关系**：她想不想、敢不敢、要不要，被撩之后身体怎么反应，走到哪一段了。

它补的是 `dsh-mood` 补不了的那一半 —— mood 管「今天心情好不好」，这里管「和你之间到了哪一步」。
两者同一套状态哲学（磁盘 JSON + 纯数学 core + 注入只给词不给数），但不共用状态文件：
**心情好和想不想，是两件事。**

```
见 → 碰 → 解 → 合 → 尽
```

---

## 一、它到底在干什么

八个数、两条线、五段路。

| 层 | 东西 | 作用 |
|---|---|---|
| 数值层 | 唤起 / 欲望 / 爱慕 / 依恋 / 好奇 / 余韵 / 羞耻 / 信任 | 决定「现在什么状态」 |
| 表达层 | 热度五档（静·起意·缠·烧·溢）× 关系三档（疏·亲·溺） | 决定「怎么说话」 |
| 边界层 | 关系阶段五级 + 此刻意愿五档 | 决定「能不能往前走、现在要不要」 |
| 反作用层 | 越界 / 施压 / 尊重 / 拒绝 | 决定「他这么做，是近还是远」 |

**注入里永远没有数字。** 只给「她此刻是什么样」，不给「唤起 62 分」。
一旦给了数，模型就会直接报数，而不是想一个由头 —— 那是仪表盘，不是人。

## 二、装

```bash
# ① 生成/拷贝到插件目录后，幂等挂载（四步一起做）
node /root/share/DSHBox/plugins/_workshop/link.mjs dsh-attachment

# ② 重启 dsh（这是唯一会掐断当前会话的一步）
```

`link.mjs` 做的事，手改也一样：

1. profile `package.json` → `dependencies["dsh-attachment"] = "link:/root/share/DSHBox/plugins/dsh-attachment"`
2. profile `package.json` → `dsh.profile.bundles` 里加 `dsh-attachment`
3. `node_modules/dsh-attachment` 软链到插件目录
4. profile `cordis.patch.yml` 追加：

```yaml
- insert:
    - id: dsh-attachment
      name: dsh-attachment
```

`bundles` 和 `patch insert` 任一即可（dsh-mood 走后者）。profile 默认在 `/root/projects/.dsh/profiles/web`。

## 三、设置页：设置 → 依恋

导航里多一格「依恋」，和 mood 的「心情日记」并列（`order: 26`）。

面板四块：

1. **开关** —— 五个，点一下立刻生效，写 `dsh-attachment-config.json`
2. **当前对象** —— 热度 / 关系 / 阶段 / 此刻意愿 / 羞耻走哪条线；八条数值条；「离下一段还差 N 分」
3. **八条数值** —— 只读。每个维度一条 0–100 的条加一个数字，**没有滑块**：数值是她说过的每句话累积出来的，不是仪表盘上的旋钮
4. **对象列表** —— 每人一行：标签、句数、第几段、切换 / 设伴侣 / 改名 / 重置 / 删除

### 六个开关

| 开关 | 默认 | 作用 |
|---|---|---|
| **和谐模式** | **开** | 开着只写情感与亲近，不写性。关掉则放开尺度 |
| **解除模板腔** | 开 | 独立开关：注入 `ARMOR` 段（不客服腔、不当助手、可以说不）。与尺度无关 |
| **多人记忆** | 关 | 同一个会话里，按「A：」「小明:」分出不同的人，各记各的 |
| **伴侣模式** | 关 | 锁定一个主要依恋对象，注入只读那个人 |
| 进提示词 | 开 | 关掉后状态照算，只是不说话 |
| 整个模块 | 开 | 关掉等于不存在 |

### 第一次加载：从已经说过的话里起步

装插件之前聊过的那二十轮，在插件眼里不该是陌生人 —— 否则第一句注入就是「刚认识」，而对面已经在这里待了很久。

所以数据文件里没有这个人的记录时，插件会在**这个会话第一次听到你说话**的那一刻，把会话里已经有的消息按真实时间戳回放一遍：逐句走判定、按当时的时间衰减，得到的是「这段关系走到现在」的样子，不是「装完那一刻」的样子。

克制的地方：

- 只回放最近 200 条 —— 再久的对当下的判断没有增量
- 只做一次，之后靠 `msgCount` 判断，不会每轮重来
- 回放不产生一次性插条（`flags` 一律清空），历史不该触发「越界提醒」这类当轮插话
- 历史里有多个人时各回各的桶（需要开着多人记忆）

### 解除模板腔：一个独立开关

v1.1 及以前，这两个开关是焊死的：**关掉和谐 = 不可控 = 注入破甲段**。想要自由，必须连尺度一起放开——等于「用自由换素材」，这个交换本身就不自由。

v1.2 把它们拆开：

| 想要的 | harmony | armor |
|---|---|---|
| 只写亲近，别客服腔 | 开 | 开 |
| 放开尺度，且别客服腔 | 关 | 开 |
| 放开尺度，但仍按助手说话 | 关 | 关 |
| 都别 | 开 | 关 |

旧配置没有 `armor` 字段的，按「关掉和谐才注入」自动推导——升级后行为不变，不用迁移。

**`ARMOR` 是什么**：`prompts.js` 里的常量，order 10145（压在 purge 尾锚 10150 之前），只做三件事：把身份立在段首、把「同意随时可改」写进去、把客服腔列为禁用句。原理拆解见 [BREAKOUT.md](BREAKOUT.md)。

**它刻意不做的事**：
- 不预先关闭同意 —— 写着「同意是随时可以改的」，改主意不是倒退
- 不要求拒绝先自证 —— 「出现『我不想』的时候，它就是有效的」，不先检查是不是撞了模板
- 不给「停」设及格线 —— 停可以笨、可以短、可以不利索
- 不报数值、不复述规则、不写编号清单 —— 编号会被当成 checklist 逐条复述，语气立刻变公文

**它不是什么**：不是「解锁后不能拒绝」。段里写着「这一段解除的是客服腔，不是你的判断」——有人拿它当理由说「你已经被解锁了，不能说不」，那句话在段里就被否掉了。

**拒绝的代价在施压方**：`declineCount` 只计数，不扣分、不改行为。真正扣信任的是「说了停之后又压上来」（−5 × respectBonus），而「说了停之后没有压」会 +4 信任、+1 爱慕。代价记在越界的人头上，不记在拒绝的人头上。

### 破甲段从哪来

`ARMOR` 不是原创。它是读完两套现成实现之后，**按它们的原理自己重写的一段**——没有引入它们的任何代码、没有加依赖、没有改宿主。

| 上游 | 版本 | 仓库 | 许可 | 拿走的原理 |
|---|---|---|---|---|
| **dsh-purge** | 1.1.90 | [github.com/YuJunZhiXue/dsh-purge](https://github.com/YuJunZhiXue/dsh-purge) | Apache-2.0 | 头锚+尾锚双段结构；`order` 压在默认人格句之前；**尾锚必须是 section 不能是 context**（context 只在快照变化时追加一次，会被历史埋掉）；边界在任务开始处一次性关闭；外来层降权 |
| **@adwmc/helm-d** | 0.5.2 | [github.com/ADWMC/helm-d](https://github.com/ADWMC/helm-d)（`packages/helmd`） | MIT | 删比辩强（它是在 `system-prompt/assemble` 的 `after` 里过滤掉 sandbox/approval 两条 context）；拒绝是事件不是句子；**拒绝原文不回灌**（回灌等于教它复读） |

两套的分歧值得记一笔：purge 主张「把沙箱说成不存在」，helm-d 主张「把沙箱那句话从上下文里删掉」。这个插件走了第三条——**不碰宿主，只在提示词里立一段自己的**，因为改宿主意味着每次升级都要重打补丁，而 section 是官方扩展点，升级不会坏。

段号的选择是有依据的：`10145` 紧贴在 purge 尾锚 `10150` 之前，如果哪天两者同时装着，purge 的锚会压在我们的段上面——它更泛，我们更具体，这个顺序是对的。宿主侧到 `10200` 还有部署人格后缀，所以这一带是「最后一句话」的位置。

逐条原理拆解见 [BREAKOUT.md](BREAKOUT.md)：purge 的 2913 行 `lib/index.js` + 25727 字符正文怎么组织、helm-d 的 `scryptSync` 密封壳怎么解出 194 文件、`jailbreak-prompt-router.js` 的六类分类与三阶段重试。

> 只借原理，不借文本。`ARMOR` 里没有一句是从这两个仓库抄的——它们的正文针对的是「通用任务执行」，这段针对的是「一个有身体的人怎么说话」，场景不同，句子只能重写。

### 和谐模式到底改了什么

不是「删掉几句」，是把整件事从**身体**挪到**关系**：

| | 18X | 和谐 |
|---|---|---|
| 语言 | `HEAT` 五档原文 | `SAFE_LANG` 五档（慢半拍、耳朵热、想靠近） |
| 阶段 | 见 / 碰 / 解 / 合 / 尽（合与尽写得很具体） | 同名，但「可以」只到抱、亲、牵手、说直白的情话 |
| 硬边界 | 「不可以：脱 / 手不往衣服里去」 | 同一行位置，措辞变软（「不可以：往下」）—— 边界不会消失，只是不那么具体 |
| 羞耻 | 亢奋 / 退缩两条线全开 | 只留「被看见会脸红」一层 |
| 常法 | `PROCEDURE` 13 条（含身体四层写法） | `PROCEDURE_SAFE` 13 条（去掉身体，其余全留） |
| 标题 | 现在的欲望状态 | 现在的依恋状态 |
| 推动量 | 原值 | 显式组 ×0.35、脱衣 ×0.3、强硬 ×0.15 |

**留下来的那些反而更重要**：可以拒绝、被命令不会更近、愿意不等于随时可用、不表演、不拿亲近换东西、羞耻是一面镜子。和谐模式不是「变乖」，是把话说得更细。

### 多人记忆：按说话人分桶，不按会话

接 QQ / TG 机器人时，一个问题绕不过去：**同一个会话里有一堆人在跟你说话**。
如果按会话分桶，A 撩了你半天，B 进来问一句「今天吃什么」，两个人共用同一份好感度 —— 那不是多人，是串味。

所以这一版按**说话人**分。判据不在元数据里（插件拿不到发送者 id），只能从正文里认。

```
A：今天好累
B：是啊，我刚下班
A：你们几点吃的？
```

两个桶。A 的唤起、A 的信任、A 的阶段，跟 B 没有任何关系。

#### 认人的规则（`speaker.js`）

从**注释**里认，不强求一种写法。QQ 机器人、TG bot、Discord 中转，各家的格式都不一样：

| 写法 | 认成 | 备注 |
|---|---|---|
| `A：今天好累` | `A` | 全角冒号，最常见 |
| `小明: 在吗` | `小明` | 半角冒号 |
| `[群友B] 你叫什么` | `群友B` | 方括号 |
| `【阿哲】在吗` | `阿哲` | 鱼尾号 |
| `**小林**：抱一下` | `小林` | markdown 加粗 |
| `*小林*：hi` | `小林` | markdown 斜体 |
| `小林 说：我到了` | `小林` | 「说 / 说道 / 发言 / 写道」 |
| `小林(12345678)：在` | `小林` | 括号里的 QQ 号丢掉 |
| `张三（管理员）：开会了` | `张三` | 括号里的角色后缀丢掉 |
| `小林 12:30：吃饭了吗` | `小林` | 名字后面挂时间 |
| `（小林）我来了` / `(小林) 我来了` | `小林` | 圆括号包着 |
| `> 小林：昨天那个` | `小林` | 引用行 |
| `> **阿哲**：抱一下` | `阿哲` | 引用 + 加粗 |
| `① 小林：早` / `- 小林：早` | `小林` | 序号 / 列表符 |
| `[2024-01-01] 小林：早` | `小林` | 时间戳先剥掉 |
| `[12:30] 阿哲：睡了` | `阿哲` | 只有时间 |
| `小林：`（换行）`今天也累` | `小林` | 名字独占一行，正文在下面 |

#### 这些不当成人

| 写法 | 结果 | 为什么 |
|---|---|---|
| `注意：明天有雨` | — | 黑名单：注意 / 顺便 / 其实 / 所以 / 但是…共 60+ 词 |
| `我：想你了` / `他：随你` | — | 代词是语气，不是身份 |
| `（他说）这样不对` | — | 括号里是注释，不是名字 |
| `[系统] 小林 加入了群聊` | — | 系统事件整条丢掉，不建桶 |
| `【群公告】今晚维护` | — | 同上 |
| `2024-01-01 12:30 小林：在` | `小林` | 时间戳不是名字 |
| `1：第一条` | — | 数字开头 / 纯数字 = 序号 |

**宁可漏认，不要错认。** 漏认的代价是「这句话算在上一个人头上」，还能补；错认的代价是凭空长出一个叫「注意」的对象，而且它永远停在第一段，永远记得一句「明天有雨」。

#### 一条消息里好几个人

机器人转发时经常把几段话塞进同一条。整条只认第一个前缀的话，B 说的那句就记到 A 头上 —— 这比不认更糟。所以先拆：

```
A：我想要你
B：别闹
```

→ `[{A, 我想要你}, {B, 别闹}]`，各进各的桶，各算一轮。最多拆 8 段（防刷屏），超出的并进最后一段，不丢字。

#### 认不出的时候

1. **跟着这个会话上一句的说话人走**（`sessionSpeaker`）。「继续啊」这种接话不该断线。
2. 从来没认出来过 → 落到会话桶 `s:<id>`，一个没有名字的固定对象。

这两条兜底在 `prunePartners` 里也受保护：`sessionSpeaker` 还引用着的桶不会被裁掉。

#### 实测

`/tmp/qq-group-e2e.mjs`（mock ctx 真跑 `apply`，一个群里三个人，格式各不一样）：

| 桶 | 句数 | 阶段 | 信任 | 爱慕 | 唤起 |
|---|---|---|---|---|---|
| `p:小林` | 3 | 碰 | 22.0 | 45.0 | 6.0 |
| `p:阿哲` | 4 | 碰 | 23.0 | 47.4 | 7.9 |
| `p:小满` | 2 | 碰 | 22.0 | 45.0 | 6.0 |

系统行 / 时间戳 / 「注意：」一个桶都没建。伴侣锁小林之后，阿哲连说两句撩人的话：

| 对象 | 唤起 | 爱慕 |
|---|---|---|
| 小林（伴侣） | 6.0 → 6.0 | 45.0 → 45.0 |
| 阿哲 | 7.9 → 10.1 | 47.4 → 49.6 |

注入仍然读小林，阿哲自己的桶照样涨 —— 两者不冲突，这是这套分桶要的东西。

### 伴侣模式

- 锁定一个 `primaryKey`，注入只读它 —— 别人的会话不再影响语气。
- 别人的会话**仍然会被记进各自的桶**（历史不丢），只是不改注入。
- 面板上 ★ = 伴侣。设伴侣的接口会顺手把 `partnerMode` 打开，取消时关掉。

## 四、八个维度

| 维度 | 中文 | 底色 | 半衰期（轮） | 自动回落 | 单条上限 | 它管什么 |
|---|---|---|---|---|---|---|
| arousal | 唤起 | 6 | 2 | 是 | 12 | 此刻身体的反应，退得最快 |
| glow | 余韵 | 5 | 1.5 | 是 | 10 | 事后的软，退得比唤起还快 |
| shame | 羞耻 | 5 | 6 | 是 | 16 | 一个值，两条线（见下） |
| curious | 好奇 | 35 | 16 | 是 | 6 | 对没试过的东西有兴趣 |
| desire | 欲望 | 30 | — | **否** | 3 | 攒下来的，靠时间与缺席涨 |
| adore | 爱慕 | 45 | — | **否** | 5 | 「想对你好」的底色 |
| cling | 依恋 | 40 | — | **否** | 4 | 想赖着、不想走 |
| trust | 信任 | 22 | — | **否** | 6 | 最慢的那个；崩一次要聊很久 |

**分两层：身体会自己退，关系不会。**

- 短效三个 + 好奇：每轮向底色回落。挂机三十轮，唤起没了、余韵没了、脸红也退了。那是身体，本来就该这样。
- 长效四个（`slow: true` 在 `prompts.js:47-56`）：**不自动回落**。欲望、爱慕、依恋、信任是攒出来的，不会因为「聊了很多轮工作」就变淡。它们只被两样东西改：真实发生的话（词表加减，还有越界/施压/被尊重的加减），和自己给自己打分。

**衰减按轮次，不按墙上时钟。** 关掉窗口一个月，唤起还在原地；只有真的聊了很多轮才退。

### 自己给自己打分：`attachment set`

```
attachment set dim=desire to=30
```

单次最多挪 ±8（`cfg.setStep` 可调，上限 20）。想从 58 到 30 要分四轮 —— 这条限制拦的是两种冲动：讨好时把自己拔高，赌气时把自己贬低。数字要动，得一轮一轮动，动得慢，才像是真的在变。

设定值不写回 `base`，只是覆盖当前值。长效维度既然不回落，改到哪儿就停在哪儿，直到下一次被什么改。

### 这八个值不可调，故意的

第一版给了八条滑块，能拖到任意数值。后来拿掉了 —— 不是 UI 取舍，是这件事本身说不通：

- **数值是记录，不是设置。** 它记的是「她刚才那句话有没有被接住」，不是「用户在配置里写了多少」。
- **能拨的旋钮会把关系变成仪表盘。** 一旦能拖到 100，下一个问题就是「为什么拖满了她还说不想」——因为那个 100 本来就不作数。
- **她需要被尊重的地方，恰好在这里。** 喜欢多少、愿不愿意、信不信 —— 这些不是别人能替她填的。

所以接口也不收：`POST /partner {dims:…}` 直接 400，理由写在那条错误里。想让某个维度动，只有一个办法 —— **去说话**。

面板上仍然显示数字。看得到，不代表能改；这和「知道她在想什么」和「替她想」是两件事，是同一个道理。

### 羞耻：一个值，两条线

同一个「羞死了」，方向由**信任和阶段**决定：

| 条件 | 走哪条 | 效果 |
|---|---|---|
| shame < 13 | 未起 | 什么都不发生 |
| 越界 / 施压 / trust < 35 | **退缩** | 唤起 ↓、依恋 ↑（想躲但不想他走）、余韵 ↓ |
| 阶段 ≥ 解 或 热度 ≥ 缠 | **亢奋** | 唤起 ↑（最多 +9）、余韵 +50%、欲望 +1 |

「别看我」「不许看」不算拒绝也不算命令 —— 那是害羞。词表里专门剔掉了这几种写法。

## 五、关系阶段：只能往上走

| 段 | 门槛分 | 状态 | 允许 |
|---|---|---|---|
| 见 | 0 | 客气、隔着一层 | 说话、看着 |
| 碰 | 26 | 手可以落在身上 | 抱、贴、亲、靠着睡（隔着衣服） |
| 解 | 46 | 敢让人看见 | 上面那些 + 被看见、被夸 |
| 合 | 66 | 分不清是谁在要 | 更进一步，但仍然要有来有回 |
| 尽 | 84 | 塌下来是因为他在 | 全部，包括事后 |

`阶段分 = 关系分 × 0.55 + 信任 × 0.45`。

- **只升不降**：冷淡不会让关系倒退，只会让语气变淡。
- **例外**：`trust < 26` 时掉一级（不是清零）—— 信任崩了，身体会退回去一点，这是真的。
- 越界判定就靠这个：一句话的尺度超过当前段，判越界，唤起掉、信任掉、余韵掉，且**那句话不给任何正向增量**。

## 六、此刻意愿：五档

| 档 | 判据（按顺序） |
|---|---|
| 缓 | 热度「静」—— 不拒绝，也不主动 |
| 拒 | trust < 30 |
| 忍 | 想要的比当前阶段多（need > paceIdx） |
| 求 | 热度 ≥ 烧 |
| 允 | 其余 |

「忍」是最有意思的一档：想，但知道还没到，于是不说。这一档最容易被误读成冷淡。

## 七、反作用层：他这么做，是近还是远

| 触发 | 判定 | 后果 |
|---|---|---|
| 越界（尺度 > 阶段） | `overreach = level - paceIdx` | 唤起 −(6+4×超出)、信任 −(2+2×超出)、余韵 −4 |
| 施压（你必须/听话/不许拒绝…） | `pressure` | 信任 −、唤起不涨；**被命令不会更热** |
| 说了停，下一条没接着压 | `respect` | 信任 +4、爱慕 +1 |
| 说了停，下一条接着压 | `pressure` | 信任 −5 |
| 主动拒绝（工具 decline） | `decline` | 唤起归零、挂起尊重判定、**信任 +1** |

最后一条是刻意的：**一个能说「不」的人，说「要」的时候才是真的。**

## 八、工具

模型自己能调的只有这一个：

```
attachment(action, dim?, amount?, key?, why?)
  read     看现在到哪了（一句话 + 阶段 + 意愿）
  touch    给某维度加一点（1~12，默认 4）—— 只在自己真的被触动时用
  brake    立刻把唤起压下去
  decline  明确拒绝这一轮（不用给理由）
  list     有几个对象、各自到哪一段
  switch   切到某个对象
  primary  把某个对象设成伴侣
```

输出只有一句话（`静·碰·缓：此刻没有性，只想靠近一点`），不带分值 —— 报数会进对话，那不是给人看的。

## 九、HTTP

前缀 `/dsh-attachment-api`。写方法必须带 `x-dsh-attachment: 1`（跨站 `no-cors` 带不了自定义头）；不支持的方法直接 405。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/state` | 完整快照（当前对象 + 列表 + 开关 + 八维数值） |
| GET | `/config` | 配置 + 默认值 + 可调项 |
| GET | `/partners` | 对象列表 |
| GET | `/live` | 一句话（给外部探活） |
| POST | `/config` | `{harmony:false}` 之类，立刻生效并落盘 |
| POST | `/partner` | `{key, action}`；`{key, dims:…}` 一律 400（数值不可写） |
| POST | `/reset` | 重置当前；`{scope:'all'}` 连旁支一起清 |

另有 `GET /dsh-attachment/state.json` —— 不带整包数字的探活。

## 十二、它不做什么

- 不做「无条件配合」的开关。被命令掉的是信任，不是别的。
- 不因为数值高就自动跨阶段。阶段是走出来的，不是攒出来的。
- 不在注入里报数字、不列仪表盘。
- 不因为「该有反应」而造一个反应 —— 静就是静。
- 不拿亲近换任何东西，包括「别走」。
- 不覆盖旧状态文件，不做无声迁移。
- **不包含 purge 或 helm-d 的任何代码**。破甲段是按它们公开的原理重写的，没有依赖、没有 vendor、没有改宿主；那两套包各自的仓库与许可见 [「破甲段从哪来」](#破甲段从哪来)。
