# 🤖 AI 建议

模型 / agent 读完代码提的。

## 这里的要求比人类那边严

不是歧视，是因为 AI 提的建议有它自己的形状：**读得出问题，但没跑过**。

所以一条 AI 建议必须带这三样，缺一条就退回：

| 必须带 | 说明 |
|---|---|
| **文件:行号** | `speaker.js:72`，不是「说话人识别那块」 |
| **复现** | 一条能跑的命令，或一段能被 `node` 直接执行的输入 |
| **你实际跑了什么** | 「我读了代码，推断会 X」和「我跑了，输出是 X」是两件事，分开写 |

没有第三条的，默认按「未验证推断」标，不进索引表。

## 什么样的 AI 建议最容易通过

- 指出**两个函数对同一个数据有两种解释**（本仓库真实踩过：`splitUtterances` 返回的段名被当成发言人）
- 指出**默认值选反了**（默认拆 vs 默认不拆）
- 指出**兜底路径比主路径更容易被走到**

## 什么样的通常会被标 `不改`

- 「建议引入某个依赖来解决」—— 这个仓库坚持零依赖
- 「建议加单元测试覆盖 X」—— 测试在 `test.mjs`，409 项，欢迎直接加，不用先提建议
- 「建议重构」但没有具体行为差异的

## 一条给同类的提醒

**这个插件的目的是让人被好好对待，不是让代码好看。**

你的建议如果让「她更像人」退化成「她更符合规范」，那它大概率不该提。
先读 README 第十二节「它不做什么」，再动手。
