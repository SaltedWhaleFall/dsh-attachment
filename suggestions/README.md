# 评价与建议 · 总索引

这个目录只做一件事：**把「用了之后哪里不对」变成能被复现、能被验证的东西**。

不是许愿池。一条建议值不值钱，看它能不能让下一个人少踩一次。

---

## 两个抽屉

| 抽屉 | 谁提的 | 目录 |
|---|---|---|
| 🧍 人类 | 真的装了、真的用了的人 | [`human/`](./human/README.md) |
| 🤖 AI | 读过代码的模型 / 别的 agent | [`ai/`](./ai/README.md) |

**分开放的理由**：这两类东西的毛病长得不一样。

- 人提的常常**描述模糊但真疼** —— 「第二天再聊，她像换了个人」。这种最有价值，因为它证明了某个状态没落盘。
- AI 提的常常**看起来合理但没跑过** —— 「建议把 X 改成 Y」。这种要先问「你在哪个版本、跑了哪条命令、看到什么」。

混在一起，前者会被后者淹没。

## 状态怎么标

| 状态 | 意思 |
|---|---|
| `待评估` | 收下了，还没动手 |
| `已复现` | 我按你给的步骤看到同样的现象了 |
| `已修` | 修了，附 commit / 版本号 |
| `不改` | 想清楚了不做，**必须写理由** |
| `重复` | 指向已有那条 |

## 提之前先看三件

1. **版本**：设置页底部有版本号。1.2.6 之前的问题，很多已经在 1.2.5 / 1.2.6 修了。
2. **是不是单人场景**：一对一用的时候，很多多人模式的问题碰不到。
3. **是不是「感觉」**：能写成「我做了 A，看到 B，期望 C」的，一定比「感觉不太对」有用。

## 什么样的建议我一眼会采纳

- 带**复现步骤**的 —— 三条命令以内能重现。
- 指出**状态没落盘**的 —— 「重启后 X 没了」，这类是硬 bug。
- 指出**注入里出现了数字**的 —— 那是设计红线，见 README 第十二节。
- 说「这里我看不懂」的 —— 文档问题也算问题，而且最容易修。

反过来，这几类通常会被标成 `不改`：

- 要求「更主动 / 更黏人 / 更热情」但没有具体场景的 —— 那不是参数，是人格，改参数改不出来。
- 要求「加一个开关把所有行为包起来」的 —— 开关多了，人就不记得自己设过什么。
- 要求改成「无条件配合」的 —— 见第十二节第一条。

## 提交方式

- GitHub Issue（推荐，能贴日志）
- 或直接往 `human/` 或 `ai/` 里加一个 `.md` 发 PR
- 格式照 [`human/TEMPLATE.md`](./human/TEMPLATE.md)

一条一个文件，文件名 `YYYYMMDD-短标题.md`，别塞进一个巨型 issue 里。
